# Лабораторная работа №1. Межпроцессное взаимодействие посредством сообщений

Реализация лабораторной работы по курсу «Распределенные вычисления» (ИТМО): библиотека IPC для
распределенной системы из N процессов с полносвязной топологией, где процессами выступают процессы
ОС Linux, а обмен сообщениями происходит через неименованные каналы (`pipe`).

## Структура проекта

```
pa1/            каталог для сдачи (все файлы в корне каталога)
├── common.h    из стартера, не модифицирован (имена лог-файлов)
├── ipc.h       из стартера, не модифицирован (MessageHeader, Message, прототипы IPC-функций)
├── pa1.h       из стартера, не модифицирован (форматы строк логирования)
├── proc.h      контекст процесса: id, число процессов N, массивы read/write дескрипторов
├── ipc.c       реализация send, send_multicast, receive, receive_any
└── pa1.c       точка входа: создание каналов, fork, фазы дочерних процессов, логирование
```

## Что реализовано

- **Создание системы процессов.** Родительский процесс по параметру `-p X` создает `X` дочерних
  процессов через `fork()` (общее число процессов `N = X + 1`, родитель имеет `PARENT_ID = 0`).
  Перед `fork()` создаются `N·(N−1)` однонаправленных каналов — по два разнонаправленных канала на
  каждую пару процессов (полносвязная топология, а не «общая шина»).
- **Контекст IPC.** Структура `Proc` хранит локальный идентификатор, N и массивы дескрипторов
  чтения/записи для каналов ко всем процессам. После `fork()` каждый процесс закрывает все
  дескрипторы, которые не предназначены для его использования; родительский процесс дополнительно
  закрывает свои write-концы, поскольку по условию он не отправляет сообщений.
- **Передача сообщений.** Сообщение = `MessageHeader` (magic `MESSAGE_MAGIC`, длина payload, тип,
  метка времени) + payload. Запись и чтение выполняются циклами полной передачи с обработкой
  `EINTR`. При чтении проверяются magic и максимальная длина payload (`MAX_PAYLOAD_LEN`).
- **Блокирующая семантика без запрещенных средств.** Read-концы каналов переведены в
  `O_NONBLOCK`; `receive()` при отсутствии данных опрашивает канал с паузой `nanosleep`.
  Функции `select()`, `poll()`, семафоры, разделяемая память и потоки не используются
  (один процесс — один поток).
- **`receive_any()`.** Опрашивает каналы всех процессов по кругу; при успешном приеме запоминает
  отправителя в поле `last_from` контекста.
- **Протокол работы дочернего процесса.** Три фазы:
  1. логирование запуска и multicast `STARTED` всем (включая родителя), тело сообщения — та же
     строка, что записана в лог; ожидание `STARTED` от всех остальных дочерних процессов;
  2. «полезная» работа (по условию работы отсутствует);
  3. логирование завершения и multicast `DONE`, ожидание `DONE` от всех остальных дочерних
     процессов.
- **Родительский процесс.** Принимает `X` сообщений `STARTED`, затем `X` сообщений `DONE`, после
  чего дожидается завершения каждого дочернего процесса через `waitpid()`.
- **Логирование.** Все события пишутся на терминал и в `events.log` с форматами из `pa1.h`
  (`log_started_fmt`, `log_received_all_started_fmt`, `log_done_fmt`,
  `log_received_all_done_fmt`). Сведения обо всех открытых дескрипторах каналов пишутся в
  `pipes.log` (при создании каналов и после закрытия неиспользуемых дескрипторов в каждом
  процессе).
- **Требования проверки.** Код рассчитан на компиляцию `clang -std=c99 -Wall -pedantic *.c`
  без предупреждений (для видимости POSIX-функций в обоих `.c` определен макрос
  `_POSIX_C_SOURCE 200809L`). stderr не используется; при успехе программа возвращает 0.

## Сборка и проверка на Linux

```bash
cd pa1
clang -std=c99 -Wall -pedantic *.c -o pa1     # сборка (при проверке достаточно: clang -std=c99 -Wall -pedantic *.c)
./pa1 -p 3                                    # запуск с 3 дочерними процессами (N = 4)
```

После запуска:

- на терминал и в `pa1/events.log` выводятся события процессов;
- в `pa1/pipes.log` — информация об открытых дескрипторах каналов;
- код возврата: `echo $?` должен вывести `0`.

Проверка отсутствия вывода в stderr и кода возврата:

```bash
./pa1 -p 5 2>err.txt; echo "exit=$?"; wc -c err.txt
```

Рекомендуемые значения для проверки: `-p` от 1 до 10 (по условию N = X + 1 проверяется от 2 до 11
процессов; значения от 1 до 10 дочерних процессов также поддерживаются).
